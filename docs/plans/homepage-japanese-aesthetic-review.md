# 首页评审方案：以日本美学为基准的个人风格审查

> 状态：评审方案（未执行）。本文只定义"怎么评审"，不预设结论，也不直接改代码。
> 评审对象：`src/components/HomePage.astro` + `src/styles/global.css` + `src/data/site.ts` 渲染出的 `ziy.one` 首页（zh / en / ja 三语）。
> 建议执行周期：一次完整评审 3～4 小时，产出一份评审记录 + 分级问题清单。

## 2. 评审目标

1. **判定一致性**：页面每一个视觉/交互决策，能否回到同一套日本美学原则上解释；不能解释的即为杂音。
2. **判定个人性**：把内容换成别人的名字后，页面是否仍然成立。如果成立，说明风格还停留在"模板级和风"，缺个人锚点。
3. **判定克制度**：元素、色彩、动效、字号层级的数量是否高于表达所需。
4. **产出可执行清单**：每条问题带位置（`file:line`）、判据、建议方向、分级，而不是主观形容词。

### 不在本次评审范围

- 内容本身写得好不好（文案价值判断）——只评排版承载与语气一致性。
- SEO / 性能优化的深度调优——只做基线检查，不做专项。
- 二级页面（`/books/ontology`、`public/works/`）——本次只评首页；若发现首页语汇与书页冲突，作为记录项而非问题项。
- 重构技术方案——评审只输出问题与方向，实施另开计划。

## 3. 美学基准：从原则到可检查判据

日本美学在评审里必须被翻成"可以指着屏幕判定的东西"，否则会退化成品味争论。下面八条原则各配一组硬判据。

### 3.1 間（ma）— 留白是结构，不是剩余空间

- 章节之间的垂直间距是否形成**可辨识的节奏**（如 1 : 1.6 : 2.6 的疏密关系），而不是全部等距。
- Hero 首屏空白占比：正文内容像素高度 / 首屏高度，目标 **≤ 45%**（即留白 ≥ 55%）。
- 是否存在"填满恐惧"——为了填空而加的装饰线、卡片边框、背景块。
- 判定方式：截图后灰度化，看留白是否连成一片贯通的"气口"，还是被分割成零碎缝隙。

### 3.2 簡素（kanso）— 简朴，去掉一切非必要

- 首屏可见元素计数（不含正文文字），目标 **≤ 7 个**：品牌、导航、语言切换、印章、标题、简介、动作链接。
- 装饰性元素（不承担信息的线、块、图标、箭头）计数，目标 **≤ 3 个**。
- 每个装饰元素单独提问："删掉它，页面会损失什么信息？"答不上来即记为问题。

### 3.3 不均斉（fukinsei）— 不对称，但有平衡

- 现有 header 是 `1fr auto 1fr` 三栏居中的**完全对称**布局；Hero 内容也基本左对齐单列。评审要判断：整页是否过度依赖对称与网格居中，缺少和式的偏移感。
- 检查是否至少有 **1～2 处刻意的不对称锚点**（如印章偏置、标题与正文的错位轴线、图版偏移），且不对称是刻意的而非 bug。
- 反面判据：不对称不能牺牲扫读——正文起始 x 轴必须仍然可预测。

### 3.4 渋み（shibumi）— 内敛的丰富

- 强调色（`--vermillion`）像素占比，目标 **≤ 2%**（印章 + 极少数状态标记）。超过即"喊出来了"。
- 页面颜色总数（不含图片），目标 **≤ 6 个有效值**，其余靠明度与线宽拉层级。
- 是否存在"第一眼就把全部信息给出"的设计；理想是首屏克制，滚动过程中逐层显出细节（悬停下划线、编号、状态标签）。

### 3.5 自然（shizen）— 不刻意，不做作

- 和风元素是否**被功能承担**：印章是不是身份标识、朱红是不是状态语义、编号是不是真正的目录序号；还是仅仅贴上去的日式贴纸。
- 反面清单（出现即问题）：假的和纸纹理贴图、樱花 / 鸟居 / 富士山图案、无理由的竖排文字、日文装饰词但页面不是 ja 语境。
- `WanderingWalker` 宠物需单独判定：它的运动是否有"自然"感（缓入缓出、偶发停顿），还是机械匀速；与"工具退到身后"的自我陈述是否冲突。

### 3.6 幽玄（yugen）— 留有余味

- 是否存在"不说完"的地方：截断的分隔线、渐隐的边缘、未闭合的网格、滚动时半露的下一节。
- 每屏是否有一个视线落点，且落点之外留有想象空间；反面是每块都被讲满。

### 3.7 静寂 / 脱俗（seijaku / datsuzoku）— 安静、脱离套路

- 动效清单：数量、时长、缓动。目标——首屏进入动效 **≤ 2 个**，单次时长 **≤ 400ms**，缓动统一（建议一条曲线走全站）。
- 是否有"网页套路"污染安静感：视差、渐显轮播、数字滚动、悬浮 CTA、弹层。出现即记问题。
- `prefers-reduced-motion` 是否被完整尊重（含宠物、平滑滚动、毛玻璃）。

### 3.8 間の文字（排版层）— 和式排版的具体尺度

- 正文行长：中日文 **28～40 全角字符**，英文 **60～75 字符**。
- 正文行高：中日文 **1.7～1.9**（现为 1.65，偏紧，需判定）。
- 字号层级数量目标 **≤ 5 级**；层级靠字号 + 字重 + 字距 + 颜色的**组合**，而不是每级都换字体。
- 字距：日文/中文正文不加字距或极小；小号 mono 标签维持 `letter-spacing`，与正文形成"疏密对比"，这一点现有实现已有，评审确认其是否一致执行。
- 标点：中日文避头尾（`line-break` / `text-spacing`）是否处理；中英混排是否有空隙抖动。

## 4. 个人风格锚点（避免变成通用 Japandi）

日本美学提供"怎么克制"，个人风格提供"克制之后剩下什么"。评审必须同时判定后者。

Ziy 的既有语义（来自 `src/data/site.ts` 文案）：

| 锚点 | 出处 | 应体现为 |
| --- | --- | --- |
| 工具退到身后 | about.lines | 界面不抢戏：无强 CTA、无营销式弹层、导航轻 |
| 少量，但持续 | works.intro | 项目列表短、状态标签（活跃 / 开发中 / 归档）成为主要信息层 |
| 把学习写成书 | books.title | 书架区块要有"物"的质感，是全站唯一允许密度更高的地方 |
| 艺术软件工程师 | hero.eyebrow | 工程感（mono 字体、编号、状态、时间戳）与手作感（印章、纸、朱）并置 |
| 三语并行 | zh / en / ja | 三种语言各自排版成立，而不是中文版塞进日文骨架 |

**个人性判定测试（必做）**：把 `profile.name`、项目名、文案全部替换成占位符后截图，问三个人"这是谁的站？"。若无人能指出任何一个不可替换的特征（印章形制、编号体例、书架结构、宠物），个人性判为不足。

**一个建议方向（供评审讨论，非结论）**：把"AI-native lab"表达为**和式的"帳"（账簿 / 记录）语汇**——编号、日期、状态、修订记录、更新于 2026.08——即把工程性做成日式记录癖，而非贴日式装饰。这条方向是否采纳，由评审决定。

## 7. 验证方法（证据怎么取）

评审必须基于同一批证据，不能各自在自己浏览器上说话。

1. **构建与本地起站**
   ```bash
   bun install
   bun run build && bun run preview
   ```
2. **截图矩阵**（共 18 张）：3 语言 × 3 断点（375 / 768 / 1440）× 2 状态（首屏 / 整页长图）。存到 `docs/plans/assets/review-YYYYMMDD/`，命名 `{locale}-{width}-{full|fold}.png`。
3. **留白与配色度量**：对整页长图做灰度直方图与朱红像素计数，得到 §3.1 / §3.4 的数值。
4. **字体回退检查**：禁用本地字体（或用未装 Hiragino / 苹方的环境）复测 ja 与 zh 页，确认回退栈不塌。
5. **可访问性基线**：
   - 对比度：正文 `--muted #66645f` on `--paper #f1eee5` 需实测 ≥ 4.5:1；小字（12px mono 标签）尤其要测。
   - 键盘走查：Tab 顺序、`:focus-visible` 朱红描边在所有交互元素上可见、skip-link 生效。
   - `prefers-reduced-motion: reduce` 下重测动效。
6. **性能/结构基线**：Lighthouse（移动端）四项分数记录即可，不做优化；同时 `bun run check` 必须 0 error。
7. **三语排版走查**：逐段对照 §3.8 的行长/行高目标，重点看 en 版（拉丁文最长）与 ja 版（假名密度不同）。

## 9. 输出物

评审结束产出一份 `docs/plans/homepage-review-YYYYMMDD.md`，包含：

**9.1 结论段**：一句话判定（通过 / 修订后复评 / 重做方向）+ 加权总分。

**9.2 评分表**：十维得分与证据链接。

**9.3 问题清单**，每条固定字段：

```
[P0] D4 朱红占比 4.1%，超出 ≤2% 判据
位置: src/styles/global.css:xxx (.status.active), HomePage.astro:187
判据: §3.4 渋み — 强调色像素占比 ≤ 2%
证据: zh-1440-full.png，朱红像素计数 4.1%
方向: 状态标签改为墨色 + 线宽区分，朱红只留给印章
影响: 视觉；无功能影响
```

分级定义：
- **P0**：破坏核心美学主张或可访问性不达标（对比度、键盘、reduced-motion）。必须改。
- **P1**：削弱一致性或个人性，可排期。
- **P2**：可选打磨、口味问题、留待观察。

**9.4 记录项**：不判对错但需留档的观察（如宠物的定位争议、书页与首页语汇差异）。

## 10. 改动准入（评审后的边界）

- 允许：`src/styles/global.css` 内的间距、字号、行高、颜色使用调整；`HomePage.astro` 内的元素删减与顺序调整；`src/data/site.ts` 的文案微调。

- 硬约束（不可因美学妥协）：
  - 内部链接一律走 `withBase()` / `import.meta.env.BASE_URL`，不得硬编码 `/ZiyOne/`。
  - `bun run check` 保持 0 error。
  - 三语并行结构不得为了某一语言的排版而破坏。
  - 静态作品页（`public/works/`）保持自包含、无依赖。
